# 布拉克星球 KPI 系統

正式入口：<https://teacher.blockplanetcamp.com/>

本系統包含 Google 登入、安親工作紀錄、備課教案建檔、成果證據、班務檢核、學生追蹤、親師溝通、主管審查與對話、月度評核、PDF 日報、月歸檔，以及 APP／LINE 通知。

## 角色與範圍

| 角色 | 主要範圍 | 可執行工作 |
|---|---|---|
| 管理員（柏翰） | 全教室、全角色 | 帳號、人員、設定、評核、報表、系統維護 |
| 全域主管（小魚） | 東橋、北區 | 查閱與評核兩教室、主管對話、學生與事項管理 |
| 教室主管（酸酸） | 東橋 | 查閱與評核東橋人員、主管對話、學生與事項管理 |
| 安親老師 | 本人 | 日誌、證據、備課教案、週整理、追蹤事項、查看評核與回覆 |
| 才藝主管（柳丁） | 才藝部門 | 備課檔案查閱、工作紀錄、KPI 評分、主管對話、雲端日報 |
| 才藝正職 | 本人 | 備課檔案、課堂日誌、證據、新生／續報與 KPI 結果 |
| 才藝 PT | 本人 | 固定班次、實到／補課／體驗、停課、證據、鐘點與續報結果 |
| 行政 | 依既有角色 | 使用行政專區；安親與才藝欄位不互相混入 |

主管不能改寫老師日誌、照片、備課、週整理或 OKR。代看功能只用於檢視，代看資料與老師本機草稿分開，且不能代替正式送出。

## 安親工作流程

1. 老師使用 Google 帳號登入。Email 必須先由管理員在人員管理完成綁定。
2. 「今日紀錄」固定包含學科內與學科外入口；兩邊只顯示各自可選的工作類型。
3. 課程型工作先從「備課教案建檔」選用既有備課檔案，授課當天只記錄教案／教材有效處、孩子共鳴環節與下次需要更新的地方。
4. 課業指導與學科外不要求關聯學生；只有班級經營可選特殊狀況學生，且不要求備課檔案。班務檢核四項各需照片。
5. 草稿同時保留在目前裝置與雲端。重新開啟可繼續編輯；正式送出前會上傳所有圖片與檔案。
6. 正式送出後建立個人 PDF，並通知同教室主管、小魚與管理員。任一 APP／LINE 管道成功才列為已送達。
7. 老師可在「我的紀錄」重開自己的完整內容；已送出的安親紀錄修改後會退回「待重新送出」，避免主管繼續審查舊版本。才藝紀錄可於授課當日更新，PT 一般課堂跨日後不開放修改。
8. 照片可一次多選、逐張移除，照片重點標記也可個別刪除；才藝備課只需課程類型、課程名稱及至少一份教案或教材附件，附件可包含文件、照片及單檔 25 MB 內的 MP4／MOV 影片，儲存後直接可用、不需主管審核。
9. 月歸檔依 `KPI月歸檔 / 教室 / 老師 / YYYY-MM` 儲存；舊版 PDF 只在歷史歸檔查看，不併入新版紀錄。

## 專案結構

```text
teacherlog/
├── index.html                 # Google 登入與正式角色導向
├── review/anqin-v2/           # 安親老師、主管與管理員工作台
├── review/talent-v2/          # 才藝正職、PT、主管與薪資工作台
├── teacher/                   # 舊版老師頁面（只保留歷史相容）
├── manager/                   # 舊版主管頁面（只保留歷史相容）
├── admin/                     # 管理員既有頁面
├── shared/                    # API、認證、通知與共用樣式
├── apps-script/               # Google Apps Script 後端
├── docs/SCHEMA.md             # 15 個 Google Sheet 資料表
└── DEPLOY_QUICK.md            # 部署與更新步驟
```

## 後端與安全

- Google ID token 由 Apps Script 向 Google 驗證，不能只靠前端解碼 Email。
- 登入後簽發 12 小時工作階段；所有資料 API（除 `ping`、`whoami`）都必須驗簽。
- 新人不可自行認領暱稱，由管理員建立人員並預綁 Google Email。
- 教師只可修改自己資料；酸酸只可查閱東橋；小魚與管理員可跨東橋、北區查閱。
- 舊稱「永康教室」在更新時自動轉為「東橋教室」，讀取時也相容舊資料。
- APP 訂閱 ID 與 LINE 綁定碼都綁定已登入帳號；LINE 綁定碼 10 分鐘失效。
- Drive 日報、教材、證據與月歸檔使用私人分享，只授權本人與正式管理鏈；角色或帳號異動會重新收斂權限。
- 只有柏翰可在管理頁刪除非管理員員工。刪除會撤銷登入與所有綁定，但用不可復原的歷史身分保留舊日報、薪資與評分關聯。

## 部署摘要

1. 將 `apps-script/_all_in_one.gs` 貼到 Apps Script 專案並儲存。
2. 每次後端結構更新後執行 `setupSheets()`；它只補欄位與遷移部門名稱，不刪既有資料。
3. 執行 `setupSystemAutomation()` 建立自動提醒與 PDF 排程。
4. 建立新的 Apps Script Web App 版本，確認 `shared/config.js` 的 `API_URL` 指向正式部署。
5. 推送 `main` 到 GitHub Pages，並以新的查詢版本號避免手機載入舊快取。
6. 依 `DEPLOY_QUICK.md` 完成登入、角色、儲存、通知與正式網址冒煙測試。

## 維護原則

- 新增人員：由管理員建立暱稱、角色、教室與 Email；不要直接開放自助認領。
- 移交班級：先更新教師與學生關聯。暫時離開用「停用」；確定離職由柏翰用「刪除員工」，不要直接刪除試算表列或歷史紀錄。
- 規則變更：更新系統內「評分標準」與 `KPI_Config`，並同步更新填寫指南。
- 欄位變更：保留舊 JSON 欄位的讀取相容，新增欄位後重跑 `setupSheets()`。
- 上線前：清除測試資料但不要刪除正式 Sheet，並依完整測試報告重跑角色驗證。

## Drive 權限邊界

Drive 產出的 PDF、照片、教材與月歸檔採私人分享，連結本身不能繞過 Google 權限。主管與老師必須使用系統綁定的 Google 帳號開啟；若 Google Workspace 管理政策禁止外部分享，系統會保留檔案但介面會回報授權失敗，需由管理員依組織政策處理。
