# KPI 系統發布驗收門檻

每次更新都必須完成以下程序。只確認按鈕存在、頁面能開啟或單元測試通過，不算完成。

## 1. 發布前完整驗收

執行：

```sh
sh tests/release-gate.sh
```

這個關卡會檢查：

- 安親、才藝、行政及主管／管理員等所有既有角色入口。
- 390px 手機與 1440px 桌面版的所有路由。
- JavaScript 錯誤、資源載入失敗、破圖、水平溢位、重複 DOM ID 與無名稱按鈕。
- 表單必填、切換後隱藏值清除、可取消勾選、多檔上傳、逐檔刪除與連點防重複。
- 草稿、正式送出、失敗回復、重試、重新整理後讀回、主管讀取與審核。
- 新版欄位與舊資料的相容，不得讓已刪除欄位在背景阻擋送出。

任何一項失敗都不得部署。

## 2. 正式環境交付驗收

前後端部署完成後，由柏翰登入管理員帳號，在系統健康檢查執行「正式雲端交付驗收」。必須取得同一次執行的 `5/5` 通過與執行編號，內容包括：

1. 正式登入身分與角色。
2. 試算表一般資料寫入、讀回與清理。
3. 安親紀錄新增、修改、兩次讀回內容比對與清理。
4. 私密照片建立、跨端預覽、PDF 嵌入與清理。
5. 教材原檔建立、內容比對與清理。

驗收資料使用唯一 `QA-` 編號，完成後必須確認試算表測試列已刪除、Drive 測試檔已移到垃圾桶。若清理失敗，整次驗收視為失敗。

## 3. 正式站複查

- 確認正式站載入的是本次版本碼，不是手機或 LINE 內建瀏覽器快取。
- 用正式入口各開一次安親、才藝、行政與主管工作區。
- 再執行核心流程：建立、儲存、讀回、編輯、送出與主管讀回。
- 確認成功訊息只出現一次；失敗時資料仍保留且可重試。
- 確認新送出的照片在重新整理及主管端仍可顯示，文件可開啟原檔。

只有發布前關卡全通過、正式雲端交付驗收 `5/5`、正式站複查無異常，才能回報更新完成。
