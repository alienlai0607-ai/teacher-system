## 一、主管摘要

本次不是只檢查畫面，而是依照老師每日使用流程，從登入、即時紀錄、草稿保存、課程備課、證據上傳、日結、主管審閱、雙向回覆、評分、PDF 匯出、月歸檔與 APP／LINE 通知完整走查。

本次已完成的核心改善如下：

1. 將「學科內」與「學科外」拆成獨立入口，工作類型不再互相混入。
2. 將「備課」與「正式教案」整合為同一份「備課教案建檔」，授課當天直接選用既有檔案，不再重複填寫。
3. 班級經營納入學科內；移除教室協作與額外工作紀錄。
4. 班級經營不要求備課教案；課程型工作才要求選擇備課檔案。
5. 支援一次選取多張照片、逐張備註、重複檔案阻擋與成果證據重新開啟。
6. 即時紀錄可以多次新增，草稿同時保存在本機與雲端；載入或儲存失敗時保留內容並提供重試。
7. 老師可從「我的紀錄」重新開啟先前內容，也能查看主管評分、建議並像對話一樣回覆。
8. 日結改為系統自動彙整，不再要求老師重寫「今天發生了什麼」。
9. 主管權限依教室隔離：酸酸只看東橋、小魚看東橋與北區、管理員看全部。
10. 匯出後依「教室／老師／年月」自動歸檔，歷史 PDF 與新版本資料分開顯示。
11. 補齊 APP 訂閱、LINE 綁定、通知重試與去重機制。
12. 修正手機與平板導覽列，其中包含「柏翰頭像被擠成獨立一格」的問題。

## 二、測試原則與範圍

### 2.1 四種使用視角

| 視角 | 核心問題 | 本次判定方式 |
|---|---|---|
| 撰寫者／老師 | 是否直覺、是否重複、能否隨時補記、資料會不會不見 | 完整填寫、關閉重開、失敗重試、手機操作 |
| 主管 | 能否快速看懂老師做了什麼、證據是否可判讀、能否追蹤回覆 | 主管列表、紀錄詳情、補件、對話、評分、匯出 |
| 老闆／管理者 | 權限是否正確、資料是否能彙整、是否可稽核 | 角色矩陣、教室範圍、月歸檔、歷史 PDF、統計 |
| 系統維運 | 外部服務失敗時是否可恢復、舊資料是否衝突 | API 錯誤、草稿、版本快取、舊檔案隔離、通知重試 |

### 2.2 涵蓋頁面

- 登入與登入後角色導向
- 今日工作台
- 新增學科內紀錄
- 新增學科外紀錄
- 班務與環境逐項檢核
- 學生個案紀錄
- 家長聯繫紀錄
- 日結與正式送出
- 本週整理
- 備課教案建檔
- 我的紀錄與歷史 PDF
- 老師查看主管評分與建議
- 主管待辦、老師紀錄、審閱、補件與對話
- 主管評分
- 月份匯出與雲端歸檔
- 更多、使用守則、評分標準、通知設定
- 管理員帳號與權限範圍

### 2.3 測試種類

- 正常流程：必填完成後儲存、重開、送出與匯出。
- 錯誤流程：空白必填、超過分數、短評語、重複照片、網路/API 失敗。
- 邊界流程：跨日後再開、同一天多次補記、不同課程型別、沒有舊資料。
- 權限流程：老師只能寫自己、主管限指定教室、小魚跨兩教室、管理員全域。
- 相容流程：手機、平板、桌機；新資料與舊 PDF 共存。

### 4.2 安全驗證

- Google 登入憑證由後端驗證，不信任前端自行宣稱的角色。
- 後端建立 12 小時簽章工作階段，過期後需重新登入。
- 除健康檢查與登入識別外，資料 API 均要求有效工作階段。
- 老師寫入時由後端綁定本人，不能竄改參數替其他老師寫資料。
- 主管讀取範圍由後端再過濾，即使修改前端請求也不能跨區取得資料。
- LINE 綁定碼為短效 10 分鐘簽章碼，不接受永久或可猜測代碼。

### 5.4 備課教案建檔

新的單一流程如下：

1. 選擇備課課程類型。
2. 輸入備課檔案名稱。
3. 撰寫正式教案的目標、流程、引導方式與評量方式。
4. 加入教材，例如 PPT、學習單、圖片、參考資料。
5. 儲存後成為可選用的備課檔案。
6. 授課當天從工作紀錄選用，不再重傳或重寫。
7. 授課後只記錄實際執行、孩子共鳴、問題及下次優化。

驗證樣本包含：兩個教學流程階段共 90 分鐘、兩份教材、完整教案；儲存後重新開啟仍為 100% 完整並保留兩份教材。

## 十二、仍需管理的外部風險

以下不是目前已知程式錯誤，但必須列入正式營運管理：

1. **Google Drive 分享連結：** 目前附件與 PDF 若採「知道連結者可查看」，連結被轉傳時仍可能外流。若日後存放更敏感資料，應改為組織帳號權限。
2. **APP 裝置訂閱：** 一個使用者目前以一個有效推播訂閱識別為主；同一帳號換手機後，需在新手機重新開啟通知。
3. **LINE／OneSignal 外部服務：** Token、服務額度、平台故障、瀏覽器封鎖通知都可能影響送達；系統會保存結果但不能保證外部平台永不中斷。
4. **歷史 PDF 命名：** 舊檔案主要由檔名推斷老師與月份；非常早期且命名不一致的檔案，可能需要管理員手動歸位。
5. **正式通知實測：** 最後應進行一筆受控真實送出，確認指定主管的 APP 與 LINE 都實際收到。
